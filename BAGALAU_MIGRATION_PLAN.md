## Ролевая модель (6 ролей MVP)

| Роль | Соответствие TestForge | Изменения |
|---|---|---|
| Владелец | — (новая) | Продуктовые решения, права, релизы |
| Суперадминистратор | — (новая) | Организации, глобальные справочники |
| Тест-администратор | — (новая) | Назначение диагностик, управление сессиями |
| Разработчик | DEVELOPER | Создание заданий (расширенный) |
| Верификатор | VERIFIER | Экспертиза заданий |
| Ученик | — (новая) | Прохождение диагностики, просмотр результата |

> Роли «Старший эксперт», «Аудитор», «Директор» — post-MVP.

## Архитектурные решения

### Что остаётся от TestForge
- FastAPI + SQLAlchemy + Alembic (backend)
- React 18 + Vite + TypeScript + Tailwind (frontend)
- PostgreSQL (Supabase)
- Объектное хранилище (Cloudflare R2 или Supabase Storage)
- Базовая структура проекта

### Что добавляется
- **Redis** (Upstash free tier) — сессии, блокировки, rate limiting
- **Background worker** — Celery или arq для тяжёлых задач
- **PWA-подход** — локальный буфер ответов ученика
- **Мультиязычность** — i18n (react-i18next)
- **2FA** — pyotp + qrcode
- **Аудит-лог** — неизменяемая таблица событий

### Модульная структура backend

```
backend/app/
├── modules/
│   ├── identity/        # Auth, 2FA, сессии, роли
│   ├── organizations/   # Школы, иерархия
│   ├── item_bank/       # Задания, версии, медиа, статусы
│   ├── review/          # Экспертиза, маршруты проверок
│   ├── test_design/     # Blueprint, шаблоны, генерация вариантов
│   ├── delivery/        # Сессии, таймер, ответы, синхронизация
│   ├── scoring/         # Ключи, рубрики, двойная проверка
│   ├── analytics/       # Агрегаты, индексы, сравнения
│   ├── reporting/       # PDF/Excel/CSV, сертификаты
│   └── audit/           # События, инциденты
├── core/                # Config, DB, Security
├── api/v1/              # REST endpoints (версионированные)
└── main.py
```

**Цель:** Полный жизненный цикл заданий

| Модуль | Задачи |

| Review | Маршруты экспертизы, замечания, возврат, утверждение |

**Типы заданий (MVP):**
- Один ответ (A/B/C/D)
- Несколько ответов
- Соответствие
- Последовательность
- Краткий ответ
- Развёрнутый ответ
- Формулы (LaTeX — уже есть)
- Изображения (уже есть)

**Критический выход:** Feature-complete alpha

### Фаза 3: Диагностика и сессии (1–20 дек 2026)
**Цель:** Проведение тестирования

| Модуль | Задачи |
|---|---|
| Test Design | Шаблон диагностики, случайный отбор по blueprint, генерация вариантов |
| Delivery | Сессия, таймер, одноразовый код, локальный буфер ответов |
| Scoring | Автопроверка закрытых, ручная проверка развёрнутых |
| UI | Экран ученика (прохождение), экран тест-администратора |

**Ключевые сценарии:**
1. Тест-админ создаёт диагностику по шаблону
2. Система генерирует N эквивалентных вариантов
3. Ученик получает одноразовый код
4. Ученик проходит тест (таймер, локальное сохранение)
5. Закрытые задания проверяются автоматически
6. Развёрнутые — вручную (анонимно)

**Критический выход:** Beta release

## Миграция БД: что меняется

### Новые сущности

```sql
-- Организации
organizations (id, name, bin, type, language, parent_id, contacts, ...)
classes (id, organization_id, grade, letter, ...)

-- Пользователи (расширение)
users: + organization_id, + 2fa_secret, + language, + position

-- Задания (расширение)
questions: + blueprint_section, + learning_objective, + competency,
           + cognitive_level, + difficulty, + question_type,
           + version, + language, + access_level

-- Blueprint
blueprints (id, subject, grade, section, objective, competency,
            cognitive_level, difficulty, question_count, ...)

-- Диагностика
diagnostics (id, name, blueprint_id, subject, grade, status, ...)
diagnostic_variants (id, diagnostic_id, variant_number, questions_json, ...)

-- Сессии
sessions (id, diagnostic_id, student_id, variant_id, started_at,
          ended_at, time_limit, status, access_code, ...)

-- Ответы
answers (id, session_id, question_id, answer_data, score, is_correct, ...)

-- Проверка
reviews (id, answer_id, reviewer_id, score, comment, status, ...)

-- Результаты
results (id, session_id, student_id, total_score, percentage,
         level, competency_scores_json, ...)

-- Сертификаты
certificates (id, type, entity_id, qr_hash, issued_at, ...)

-- Аудит
audit_log (id, user_id, action, entity_type, entity_id,
           details_json, ip_address, created_at, ...)
```

### Изменения существующих таблиц
- `questions` — расширение метаданных (blueprint, competency, cognitive_level, difficulty, version, language)
- `users` — добавление organization_id, 2FA, language
- `media` — привязка к organization_id для изоляции

## Инфраструктура (бесплатные сервисы)

| Компонент | Сервис | Лимит |
|---|---|---|
| Backend API | Render Free | 750ч/мес, auto-sleep |
| Frontend | Vercel Free | 100GB/мес |
| PostgreSQL | Supabase Free | 500MB, 2 проекта |
| Object Storage | Supabase Storage Free | 1GB |
| Redis | Upstash Free | 10K запросов/день |
| Background Jobs | Render Free Worker | 750ч/мес |
| Домен | Cloudflare (бесплатный DNS) | — |
| SSL | Автоматически (Render/Vercel) | — |

> ⚠️ Для production-пилота бесплатные лимиты могут не хватить. Нужен план upgrade.

## Технические риски

| Риск | Вероятность | Влияние | Митигация |
|---|---|---|---|
| Не хватит времени на 15 модулей | Высокая | Критическое | Жёсткий приоритет, cut scope при угрозе |
| Бесплатные лимиты не выдерживают пилот | Средняя | Высокое | План быстрого upgrade |
| Потеря ответов ученика | Низкая | Критическое | PWA-буфер, идемпотентная синхронизация |
| Утечка заданий | Низкая | Критическое | Водяные знаки, запрет копирования, аудит |
| Один разработчик = bottleneck | Высокая | Высокое | Модульная архитектура, чистые интерфейсы |
